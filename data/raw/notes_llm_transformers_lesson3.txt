Part A — What Is a Large Language Model?
A Large Language Model (LLM) is a neural network with billions of learnable parameters, trained on enormous text corpora to model the statistical patterns of human language. Once trained, it can generate fluent text, answer questions, write code, translate languages, and reason over documents — all through a single, unified architecture.
A.1 Why Scale Changed Everything
Earlier NLP systems were task-specific: a sentiment analyser could not summarise text; a machine translation model could not answer questions. Each required separate training pipelines, hand-crafted features, and domain-specific rules.
The breakthrough insight behind LLMs is simple: if you train a single model on enough data with enough parameters, it spontaneously develops the ability to perform many tasks without explicit instruction. This is called an emergent capability — a skill that was never directly trained for but arises from scale.

Emergent Capabilities
Some abilities — multi-step arithmetic, chain-of-thought reasoning, analogy solving — only appear reliably above a certain scale threshold. Below that threshold the model performs at chance; above it, performance jumps dramatically. This non-linear behaviour is one of the most studied (and debated) phenomena in current AI research.

Part B — The Transformer Architecture
The Transformer, introduced by Vaswani et al. in 2017, is the architectural backbone of every modern LLM. Understanding it is not optional — every technique in this course (RAG, fine-tuning, prompt engineering, RLHF) makes more sense once you see what happens inside the model.
B.1 Why the Transformer Replaced RNNs
Before the Transformer, sequence modelling relied on Recurrent Neural Networks (RNNs) and their improved variants, Long Short-Term Memory networks (LSTMs). They worked by processing text one token at a time, left to right, maintaining a hidden state that summarized everything seen so far.
RNN / LSTM — Problems
• Sequential processing: token N cannot start until token N-1 is done. Cannot
parallelize across a sequence.
• Vanishing gradient: information from token 1 is diluted across hundreds of time steps — the model forgets early context.
• Fixed-size hidden state: no matter how long the input, the entire past is
compressed into a single vector.
• Slow training on modern GPU/TPU
hardware because parallelism across the
sequence dimension is impossible.
Transformer — Solutions
• Parallel computation: all positions in the sequence are processed simultaneously.
Utilizes GPU matrix operations fully.
• Direct token-to-token connections via attention: token 1 and token 500 can
directly influence each other with equal
ease.
• Explicit attention weights: the model learns which tokens to attend to for each
prediction, with no information bottleneck.
• Scales gracefully: doubling the hardware roughly doubles training throughput — the architecture was designed for scale.

A residual connection adds the input of the sub-layer to its output (prevents vanishing gradients), then layer normalisation stabilises the distribution before the next layer.
Each token's representation passes through a two-layer MLP applied independently and identically at every position. This is where much of the model's "knowledge" is stored.

After all layers, a linear projection maps the final hidden state to a vector of vocabulary size. Softmax converts it to a probability distribution. The model samples the next token from this distribution.
B.3 Self-Attention in Detail
Self-attention is the mechanism that allows every token to "look at" every other token and decide how much to borrow from each. Here is the calculation, step by step:
Step 1 — Create Q, K, V matrices
Each token embedding is linearly projected into three separate vectors using learned weight matrices: • Query (Q) — what this token is looking for
• Key (K) — what this token advertises about itself
• Value (V) — the actual content this token will contribute to others
Step 2 — Compute raw attention scores
For each pair of tokens, compute the dot product of the Query of one with the Key of the other. A high score means these two tokens are highly relevant to each other:
scores = Q × Kᵀ
Step 3 — Scale and normalise
Divide by the square root of the key dimension (d_k) to prevent extremely large values that would cause vanishing gradients after softmax:
scaled_scores = scores / √d_k
Apply softmax row-wise so each row sums to 1 — these are now attention weights (how much each token attends to every other):
attention_weights = softmax(scaled_scores)
Step 4 — Weighted sum of Values
Multiply the attention weights by V. Each token's output is a weighted combination of all Value vectors — essentially borrowing information from tokens it paid attention to:
output = attention_weights × V
The full formula, as written in the original paper:
Attention(Q, K, V) = softmax( QKᵀ / √d_k ) × V
Why Multiple Heads?
Multi-Head Attention runs the attention calculation H times in parallel, each head using different learned Q/K/V projections. Different heads specialise in different relationship types: one head might track syntactic dependencies (subject→verb), another might track coreference (pronoun→antecedent), another semantic
similarity. Outputs of all heads are concatenated and projected, giving the model a richer representation than any single attention pass.
B.4 Worked Example — What Attention Sees
Consider the sentence: "The trophy did not fit in the suitcase because it was too big."
The word "it" is ambiguous — does it refer to the trophy or the suitcase? A human reader resolves this through world knowledge (things can be too big to fit inside other things). An LLM resolves it through attention:
• The token "it" will assign a high attention weight to "trophy" because the adjective "big" is more consistent with trophies overflowing containers than suitcases being oversized.
• This resolution happens automatically from training — the model learned the pattern from millions of similar sentences.
• This is the "pronoun coreference" task that earlier NLP systems required dedicated hand-crafted modules to handle. Attention learns it implicitly.

Why Decoder-Only Won
Decoder-only models are auto-regressive: they generate one token at a time, feeding each output back as input. This turns every task — translation, summarization, coding, Q&A — into the same operation: "predict the next token." The simplicity of this unified formulation, combined with scale, is why decoder only LLMs dominate modern AI products.

Term Definition

Part C — How ChatGPT Is Trained
A raw pre-trained Transformer produces fluent text, but it will happily continue a harmful prompt, ignore instructions, or generate offensive content — because it only learned to predict the next token, not to be helpful or safe. Converting a base language model into a useful, instruction-following assistant like ChatGPT requires three carefully orchestrated training stages.

C.2 Stage 1 — Pretraining
Pretraining is the most computationally expensive phase — GPT-3 required approximately 3,640 petaflop-days of compute; GPT-4 is estimated at 10× more. The objective is deceptively simple:
Next-token prediction: maximise P(token_n | token_1, token_2, …, token_n-1)
Given all previous tokens, predict the next one. Repeated across trillions of (token, context) pairs, the model must implicitly learn:
• Grammar and syntax — to produce grammatical text
• World knowledge — to predict factually plausible continuations
• Reasoning patterns — to predict logically consistent sequences
• Code structure — to predict syntactically valid programs
Self-Supervised Learning
No human labelling is needed for pretraining. Every text document automatically provides millions of training examples: for a document with N tokens, there are N-1 (context, next-token) pairs. This is why pretraining can scale to trillions of tokens — the data labels itself.
C.3 Stage 2 — Supervised Fine-Tuning (SFT)
After pretraining, the base model knows a lot — but behaves like a text-completion engine, not an assistant. If you prompt it with "Explain quantum entanglement," it might continue with more questions or generate random text, not an explanation.
SFT bridges this gap by showing the model what good instruction-following looks like:
Phase Detail
Data creation Human contractors write diverse prompts covering many tasks (summarise, explain, translate, code, reason, role-play) and write ideal model responses for each.
The pre-trained model is continued-trained on these (prompt, ideal response) pairs
Fine-tuning
using the same next-token prediction loss — but now the target sequence is the ideal response, not random internet text.
Result
The model learns the format, tone, and structure of helpful responses. It begins following instructions reliably, using the format "Here is the answer: …" rather than continuing the prompt as raw text.
C.4 Stage 3 — Reinforcement Learning from Human Feedback (RLHF)
SFT improves instruction following, but it only trains on what annotators explicitly wrote. RLHF goes further: it trains the model using human preferences as a reward signal, allowing it to optimise for qualities that are hard to specify in advance — helpfulness, harmlessness, appropriate tone.
Step 1 — Collect Preference Data
For the same prompt, the SFT model generates multiple candidate responses. Human raters rank them from best to worst. These rankings form a preference dataset.
Step 2 — Train a Reward Model (RM)
A separate neural network (the reward model) is trained to predict human preference rankings. Given a (prompt, response) pair, it outputs a scalar reward score. High score = a human would prefer this response.
Step 3 — Optimise the LLM with RL
The SFT model (now called the policy) generates responses. The reward model scores each response. The policy is updated via Proximal Policy Optimisation (PPO) to generate responses that maximise the reward score.
A KL-divergence penalty term constrains the policy from drifting too far from the SFT model — without it, the model might find adversarial responses that fool the reward model but are nonsensical:
Objective = E[r_RM(prompt, response)] − β · KL( π_RL ‖ π_SFT )
RLHF in Practice — Challenges
RLHF is notoriously difficult to get right. The reward model is imperfect, and the policy can over-optimise it ("reward hacking") — producing responses that score highly but are sycophantic or superficially polished rather than genuinely correct. This is an active research area. Newer approaches such as Direct Preference Optimisation (DPO) and Constitutional AI (CAI) aim to sidestep some of these problems.

Lesson Summary
Part A — What Is an LLM?
• LLMs are very large neural networks — billions of parameters — trained on trillions of tokens of text.
• Scale produces emergent capabilities: skills the model was never explicitly trained for but acquires beyond a parameter threshold.
• LLMs generalise across tasks using zero-shot and few-shot prompting, replacing dozens of task specific models.
• Key limitations: hallucination, knowledge cutoff, no persistent memory, unreliable formal reasoning.
Part B — The Transformer
• The Transformer replaced RNNs by enabling parallel computation across all positions in the sequence.
• Data flows: tokenise → embed → positional encode → N × [self-attention + FFN + residuals] → softmax over vocabulary.
• Self-attention computes Attention(Q, K, V) = softmax(QKᵀ / √d_k) × V, learning which tokens to attend to for each prediction.
• Decoder-only (causal) models dominate LLM products because every task reduces to next-token prediction.
Part C — How ChatGPT Is Trained
• Stage 1 — Pretraining: self-supervised next-token prediction on massive internet-scale corpora. • Stage 2 — SFT: fine-tuning on human-written (prompt, ideal response) pairs to teach instruction following.
• Stage 3 — RLHF: optimising with a reward model trained on human preference rankings to align with human values.
• Base models complete text; instruction-tuned models answer questions — the distinction matters for every downstream task.
